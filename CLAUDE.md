# CLAUDE.md

Static recompilation of **Beat the Beat: Rhythm Paradise** (Wii, PAL `SOMP01` rev 0) to native code. Same requirements and scope as the sister project Qilin1066/GBTGhoulies--QilinRecomp. This repository is Qilin1066/RhythmHeavenFever--QilinRecomp (the owner's name for it since 2026-11-21, after the game's North American title; it was BeatTheBeat-QilinRecomp before that, and BeatTheBeat-QilinComp up to 2026-11-20; GitHub redirects the old names, and the local folder may still have one). What players see is still named after the PAL game, Beat the Beat: Rhythm Paradise.

## Requirements (non-negotiable)

- **Efficiency first, then accuracy, and fail loudly.** Never paper over an unknown: stop with a clear error (`rt::Stop`, exit codes, CMake `FATAL_ERROR`).
- **C++23** everywhere: recompiler, runtime and generated code.
- **Vulkan 1.3 only** for graphics. No OpenGL, D3D or Metal backends (macOS goes through MoltenVK).
- **Static recompilation only.** No interpreter, JIT or emulator at runtime, not even as a fallback.
- Targets: 64-bit **Windows, Linux, macOS** on **x86-64 and ARM64**. The low-end reference is ARM boards like the **Raspberry Pi 4**. No iPadOS, no 32-bit.
- Compiler minimums: GCC 14, Clang 19, Apple Clang (Xcode 16), MSVC 2022 17.10.
- No GPL code. The only third-party data is the CC0 decomp symbol list in `third_party/rhf/`. Third-party libraries (SDL3, Khronos' Vulkan headers, Dear ImGui for the settings menu as in the other recomps; glslang only with `-DQILIN_BUILD_SHADERS=ON`: all permissive) are fetched by CMake at configure time, pinned by SHA-256, and never committed. Keep dependencies to the fewest possible (the owner's standing preference). The shaders' SPIR-V is committed with a stamp of their GLSL's hash; after editing a shader, configure once with `-DQILIN_BUILD_SHADERS=ON` and commit `recomp/runtime/shaders/spirv`. (The project itself is GPL-3.0 since 2026-11-21, the owner's choice; this rule is about other people's code, which still isn't copied in.)
- Never commit game data or anything derived from it: `main.dol`, `gen/`, `cfg.json`, ported symbol lists. These are gitignored.

## Layout

- `recomp/src/`: `dol` (loader, known-build SHA), `decoder` (table-driven, 222 ops, X-macro `QILIN_PPC_OPS`), `cfg` (function discovery, jump tables, coverage), `lifter` (one C++ function per guest function), `main.cpp` (the `qilin` CLI).
- `recomp/src/libraries.*`: the library plan in code (lift, replace or drop, by PAL range) and `lift_anyway` (functions lifted out of replaced libraries, by name). Keep it in step with the table in `docs/code-analysis.md`.
- `recomp/runtime/`: `guest.hpp` (Context, memory, flag and arithmetic helpers, `Stop`), `dispatch.cpp` (`rt::call`, SPRs, time base). The game: `run.cpp` (`qilin_run`: start-up as `__start`, stop reports), `machine.*` (guest memory), `native.*` (registry: `QILIN_NATIVE(name)`, by the decomp's name, never by address), `os.cpp` (native OS functions).
- `recomp/tests/tests.cpp`: unit tests (`ctest`).
- `tools/check/verify_decoder.py`: compares the decoder with binutils objdump.
- `tools/difftest/`: runs lifted code and the original under Unicorn and compares the results, one worker per CPU. Runs on Linux, macOS and Windows. Trials are seeded per function, so `--only`/`--range` replay a full run's trials exactly.
- `tools/analysis/port_symbols.py`: ports US decomp names to PAL. `recomp/src/symbols.*` (`qilin symbols`) is the same port in C++, for the downloads (no Python on a player's computer): the two must write the same list (checked on the supported `main.dol`, 2026-11-28); change both together.
- `recomp/src/identify.*` (`qilin identify`): the launcher's check of the chosen folder (ADOPTING.md's contract; Punch-Out's, adapted).
- `tools/player-kit/`: the players' downloads (Windows, Linux x86-64 and ARM64, macOS), as Toy Commander's and Punch-Out's. `launcher/` is Toy Commander's launcher folder, copied verbatim (never edit it here; `LAUNCHER_VERSION` says which); `games.sh` writes `kit/game.txt` (steps: `qilin symbols` then `qilin lift --runtime`); `package*.sh`, `smoke-linux.sh`, `check-macos.sh`, `macos.cmake`; workflows `.github/workflows/player-kit*.yml`. `-DQILIN_PLAYER_KIT=ON` builds the kit (`libbeatthebeat_kit.a`, the runtime, linked whole because natives register from static initialisers; `libbeatthebeat_libs.a`; `build-flags.txt`); `-DQILIN_LAUNCHER=ON` builds the launcher and `beatthebeat_runtime_check` (the whole game program with stand-in tables) without one.
- `tools/analysis/lowmem.py`: boot values from a Dolphin MEM1 dump, against the runtime's.
- `recomp/src/hwaccess.*` (`qilin hwaccess`) and `tools/analysis/runtime_todo.py`: the runtime's to-do list (replaced functions lifted code calls, its direct hardware accesses). Their output is game-derived: never commit it.
- `tools/difftest/build_ubsan.py`: the UBSan harness through zig's Clang, on any host.
- `docs/`: design and results. Keep them current. `recompiler-core.md` covers the decoder, CFG, lifter and difftest; `runtime.md` the runtime; `roadmap-and-design-targets.md` is the roadmap.

## Build and check

```sh
cmake -S . -B build -DCMAKE_BUILD_TYPE=Release -DQILIN_WERROR=ON
cmake --build build --parallel
ctest --test-dir build --output-on-failure
build/qilin coverage path/to/main.dol          # exits 3 today: 102 words unclassified (48 in text0, 54 in text1); it should be 0
build/qilin lift path/to/main.dol --out gen
```

Differential test (`pip install unicorn`; on Windows with the Visual Studio generator the harness is `build-gen/Release/qilin_difftest.exe`):

```sh
cmake -S . -B build-gen -DQILIN_GEN_DIR=$PWD/gen && cmake --build build-gen --target qilin_difftest --parallel
python3 tools/difftest/difftest.py --harness build-gen/qilin_difftest --dol path/to/main.dol --gen gen [--only A,B] [--range LO-HI] [--jobs N]
```

The runtime (its own lift: replaced libraries call native code; `pal_symbols.txt` and `gen-rt/` are game-derived, never commit them):

```sh
build/qilin symbols path/to/main.dol --decomp third_party/rhf/SOME01 -o pal_symbols.txt   # or port_symbols.py --symbols-out
build/qilin lift path/to/main.dol --out gen-rt --runtime --symbols pal_symbols.txt
cmake -S . -B build-rt -DQILIN_RUNTIME_GEN_DIR=$PWD/gen-rt && cmake --build build-rt --target qilin_run --parallel
build-rt/qilin_run path/to/disc          # a window (SDL3 + Vulkan), sound, the keyboard as the remote
QILIN_HEADLESS=1 build-rt/qilin_run ... # no window (tests, scripted runs: QILIN_INPUT, QILIN_RUN_SECONDS, QILIN_AUDIO_DUMP)
```

Before a milestone commit, all of these must hold: tests pass, warnings are clean (`QILIN_WERROR`), generated code is warning-free under GCC, Clang and MSVC, and the difftest has **0 unexplained mismatches**. Any new Unicorn quirk goes in `known_difference` with a comment explaining why.

## Known facts worth not rediscovering

- The DOL SHA-256 is `2e0368359106a2eef773c70ef083e89aafe1e49603eefc7f16b9ed414cd098fe`. Entry point, sections and real start-up register values (r1 0x803E7488, r2 0x8032A680, r13 0x80328500) are in `docs/dol-analysis.md`.
- Broadway divide by zero or overflow: `divw` gives 0xFFFFFFFF for a negative dividend, else 0; `divwu` gives 0. (Unicorn differs; this is a known difference.)
- Generated code under MSVC: `[[maybe_unused]]` covers only a declaration's first declarator (so one declaration per local), and C4702 is disabled for generated code (optimiser-dependent).
- FPSCR is only touched by replaced or dropped code (base, OS, MetroTRK), so lifted code doesn't model it. `OSInit` calls `PPCSetFpNonIEEEMode`: the game runs with NI = 1 (denormal operands and results become signed zero, per the IBM 750GX/GL manual).
- Where Broadway's FP result has no source (fmuls-family frC that isn't a single, compares of denormals, `fres`/`frsqrte` tables), lifted code stops (`rt::fp_unknown`) or the function isn't lifted. Don't guess these, and don't take them from Dolphin's code (it's GPL), nor from running a test under Dolphin (that reads out Dolphin's code). One owner-approved exception (2026-11-19; no homebrew-capable Wii to measure on): the game's runtime build defines `QILIN_APPROX_ESTIMATES`, so `frsqrte`/`fres` give the exact result rounded to 12 fraction bits (IBM's stated accuracy), marked APPROX; the difftest build still stops there.
- Paired singles follow IBM's *PowerPC 750CL RISC Microprocessor User's Manual* (cited by title; the repo doesn't link to or include copies of it): `lfs` and single-precision results fill ps0 and ps1; `lfd`, double ops and `fmr` leave ps1 alone (CodeWarrior saves FPRs with `stfd` and `psq_st`); GQR quantisation rounds toward zero and clamps. Unicorn has none: `tools/difftest/paired.py` is the reference model (keep it independent of `guest.hpp`).
- Register dataflow (`run()` in `lifter.cpp`): sync points are `@OUT@`/`@IN@` markers; stores are the dirty registers, reloads the live ones. Any runtime helper that writes a local by reference must be listed in `writes()` (today only `rt::psq_l`).
- GCC can't be run on the owner's PC, so CI is the only GCC check. Its compiler messages are annotations on the commit (`.github/matchers/compilers.json`), readable without signing in: `https://api.github.com/repos/Qilin1066/RhythmHeavenFever--QilinRecomp/check-runs/<job id>/annotations`. GCC's `-Wshadow` also flags a local type or variable reusing a file-scope name (Clang's and MSVC's don't): CI was red from acba58e to 2438e35 over a test's local `struct Bad`. Check CI after pushing.
- Clang on Windows without installing LLVM: `pip install ziglang`, then `python -m ziglang c++ -std=c++23 -O2 -Wall -Wextra -Wpedantic -Wshadow -Werror -ffp-contract=off -fno-fast-math -Igen -Irecomp/runtime -c gen/x.cpp -o x.o` (not `-fsyntax-only`: zig adds `-c`). GCC 14 still has to be checked on Linux.
- UBSan: `-DQILIN_UBSAN=ON` (GCC/Clang), or on Windows `python -I tools/difftest/build_ubsan.py --gen gen --out <dir>` (zig's Clang). v0.10.0: no undefined behaviour in the full run.
- CR bits only where read: not worth doing. Clang already folds dead CR updates (`cr` is a local); CR reaching a sync is observable.
- The difftest's time base is deterministic (`QILIN_DETERMINISTIC_TIME` in the harness, emulated `mftb` under Unicorn): the k-th read of a trial is `0x100000000 + k * 0x1000`, so every trial replays exactly with `--only`.
- A difftest failure that doesn't replay may be hardware: the development PC's overclocked non-ECC RAM flipped bits (found 2026-11-18 with a buffer stress test). Every 16th trial checks MEM1 against the image on both sides.
- Unicorn scans code hooks linearly: register one hook per text section and filter in Python, never one per address (30x slower).
- Special-register reads (not LR, CTR, XER, GQRs) are detected dynamically in the difftest (calls through function tables, such as `__init_cpp`'s constructors, defeat static call trees).
- Unicorn's FP: it ignores NI (the harness counts flushes, so these are known differences), and `fctiwz` gives a 0 high word and `0x80000000` on positive overflow (corrected by hooks).
- The harness treats a top-level return to anywhere but the caller as a bad return, as lifted callers do.
- The difftest's entry stub at 0x80002F00 must be in the starting state on both sides (a function scanning memory reads it).
- Unicorn quirks:
  - its XER API doesn't set the flags, so the harness uses a stub
  - stale translation cache: call `ctl_remove_cache`
  - its write hook misses `dcbz`/`stmw`/`stswi`, so the harness compares all of MEM1
  - it reports the `dcbz` fault address differently
- Bring-up loop: run `qilin_run`, read the stop (`no native code yet for X [lib], called from Y`), add `QILIN_NATIVE(X)` or, if X only works on guest structures, add its name to `lift_anyway` and lift again. Check what X does in the listing (`qilin insns`) before writing it.
- The native functions register from static initialisers, so their sources are `qilin_run`'s own (a static library would drop them).
- `OSInit`'s arenas come from low memory that IOS and the apploader fill in. The runtime's values are from `OSInit`'s own defaults and are still to be confirmed with a Dolphin memory dump at the entry point: `tools/analysis/lowmem.py mem1.raw` compares (`docs/runtime.md`).
- Cross-compile check without Linux or a Mac: `python -m ziglang c++ -target {x86_64,aarch64}-{linux-gnu,macos} ...` with the flags above, per source file. zig's macOS headers lose `DBL_MIN` if `<chrono>` comes first, so the runtime uses `std::numeric_limits`, not the `<cfloat>` macros.
- `OSLockMutex` and the thread, message and alarm code are bookkeeping on guest structures over `OSDisableInterrupts`, the context switch (`SelectThread`) and the time base. `OSGetCurrentThread` and the SDK's inlined clock macros read low memory.
- OSThread layout, from the code: context at +0 (SRR0 +408, SRR1 +412, context state +418, GQRs +420, ps1 +456), state +712 (1 ready, 2 running, 4 waiting, 8 moribund), priority +720, queue +732, links +736/+740, stack +772/+776. Low memory: current context 0x800000D4, FPU context 0x800000D8, active list 0x800000DC/E0, current thread 0x800000E4.
- Disassembly with names: `qilin insns` to a listing, then join with the PAL symbol list (the session used a small script; keep both outside the repo).
- The decomp's placeholder names (`fn_80038350__Fv`) carry US addresses; the PAL address is in the symbol list.
- Size alignment can't place a run of equal-size functions: it put base's register accessors three functions early (fixed by `SIGNATURES` in `port_symbols.py`). A native whose name could be misplaced states its code (`QILIN_NATIVE_CODE`), and binding fails if it differs. Base starts at `0x800DA6C0`; the three functions before it are the game's.
- The extracted disc is the owner's and lives outside the repo (ask for its path; `sys/`, `files/`). `qilin_run` takes the folder. A `.wbfs` can't be read (Wii disc key).
- GX is replaced at its API (its register writes go through pointers in memory, which can't be caught cheaply). Lifted code's FIFO stores (constant address 0xCC008000, found by `hwaccess`) become `rt::fifo_st*` calls in the lifter. Prefer lifting pure GX functions (object init/get, arithmetic) and decoding their output natively; native `GXInit` runs the lifted `__GXInitGX` for the SDK's defaults. Check a candidate is pure: no `hwaccess` hits, no `lwz rX,-1568(r2)` (GX's state pointer), no hardware-touching calls.
- Before writing a native, read how the SDK function and its callers use the result (e.g. `WPADGetStatus() == 3` in `KPADInitEx`, `SCCheckStatus() == 1` busy in `OSInit`). Where a value is the console's own (a size, a constant), lift the function that returns it instead of copying the number.
- Safe points (v0.15.0): native-call entry and every lifted backward branch (`rt::poll_due`/`rt::poll`, with `c.r[1] = r1`), besides enabling interrupts and idle. I/O completions get `kIoLatency` (1 ms): instant ones overtook the game's own bookkeeping (it sets "loading" after issuing a read) and hung it. Periodic interrupts catch up; Windows needs `timeBeginPeriod(1)` or idle waits round up to 15.6 ms and audio frames are lost.
- AX's stereo mode has no main S channel (`__AXNextFrame`'s DSP cycle budget: set-up 733/829/925 for stereo/surround/DPL2, one 96-sample channel each), so the DSP drops S in stereo; AXFX's reverb does send to S there. A question about what the DSP does can often be answered from the CPU side's command list and its cycle estimates. Surround (SC 2) is Pro Logic II: L, R, Ls, Rs per bus, Rs in aux C's mix slots (NW4R's `CalcMixParam`); the two-channel encoding is APPROX (`dpl2.hpp`, all-pass pair designed by `tools/analysis/design_dpl2_allpass.py`).
- AX is lifted whole; the native DSP takes mail `0xBABE0080` + the command list (command 0 studio, 1-3 mix buffers by mode, 4 first PB; PB next at +0, state at +16; VPB.pb at +40) and posts the task's resume callback. `DSPAddTask` must run the init callback before returning (AX spins on it).
- MEM1's arena ends at `(0x81800000 - fst.bin size) & ~31` (the apploader's place for the file table); the runtime's scratch lives there. The game makes one heap of each arena (`memInitHeap`), so the bounds are its heap sizes.
- Interrupts reach lifted code only at safe points: `OSEnableInterrupts`/`OSRestoreInterrupts` turning them on, and the idle scheduler. `OSLoadContext` throws `rt::Resume` to unwind an interrupt handler; it stops anywhere else.
- The renderer records on its own thread (2026-11-20): anything that records into a command buffer goes through `record(...)` and runs on the render thread (`r_` functions, `rcur()`); the game side never touches command buffers, descriptor pools or `g_rec`. Before the main thread uses the renderer (paused frames, display changes) or anything waits on a fence, `drain()`/`wait_submitted()`. The known strap-screen stall was seen once in about 20 runs with it (the same family: about 5.3 MB read, 0 voice frames), against about 1 in 30 before.
- Hot spots: `QILIN_SAMPLE=1` on a build with `-DQILIN_DEBUG_SYMBOLS=ON` (a separate build dir, e.g. `build-rt-prof`: the whole game recompiles) names the hottest functions (Windows). Run it hidden with a scratch `QILIN_NAND`.
- Efficiency: measure first (`QILIN_PROFILE=1`). The renderer's caches follow the console's coherency rule (`coherence.*`): only flushed or DMA-written pages are re-checked; never hash textures per draw. `-DQILIN_RUNTIME_CHECKED=OFF` halves lifted code's time (checked stays the default for bring-up); LTO gave nothing measurable. The TEV configuration is specialisation constants (`Spec`, ids 0-68, matching `shaders/gx.frag`): keep the two in step, and keep per-draw values in the uniform block, not in the key. The pipeline cache lives in the game's data folder (`game_data_dir()`, `pipelines.bin`).
- UI conventions are shared with the other Qilin recomps (`docs/naming.md`; the sister repos are Qilin1066/GBTGhoulies--QilinRecomp, ApbArcade--QilinRecomp and PunchOutWii--QilinRecomp): window named after the game at the largest whole multiple that fits, F11/Alt+Enter fullscreen, data folder `<per-user data>/qilin/beatthebeat`, settings file `beatthebeat.ini` with presets, the ImGui settings menu (F1/Esc, controller Back+Start; Close and Quit top right; Controls/Display/Game; press-to-bind controls kept in `[controls]`; F3 frame times; CRT look; pauses the game, saves on close; `menu.*`, `pause.*`; Punch-Out's `punchout/src/menu.cpp` is the model, matched 2026-11-20), SDL gamepads plus keyboard on player 1 (the owner chose this one's keys, 2026-11-20: A = A, Right Shift, Right arrow or Space; B = B, Left Shift or Left arrow; d-pad I/J/K/L and Up/Down; Enter, Backspace/Tab as the others; controller shoulders right A, left B). Keep them in step when either side changes. A symbol lookup by nearest-lower address misattributes code outside the named ranges (the 0x80004000 start-up code isn't the game's first function).
- Library split (`docs/code-analysis.md`): lift game/NW4R/MSL/runtime/etc. (74%); replace OS, DVD, GX, AX, pad, WPAD, NAND… (25%); drop MetroTRK/NdevExi2A (1%).

Test these only fullscreen (the owner's desktop isn't lockable): it switches the owner's monitor to 120 Hz for the run.
- Lag and stutter (after v0.16.0): the audio queue is held at `[audio] latency_ms` (10 ms, raised to the device's floor: its period plus 4 ms, 14 ms on the owner's Scarlett Solo with a 10 ms period, measured with no underruns) by SDL's resampling ratio, the run report prints its depth and underruns; with vsync the time base runs at the display's refresh when within 0.5% (`set_time_base_speed`, set once before the game's threads start); fullscreen switches to a 60/120 Hz mode when the desktop's refresh can't lock (the owner's desktop is 75 Hz: windowed play there judders, every fourth frame held a refresh); pipelines met before are made at start from `pipelines.keys`; FIFO uses two swapchain images; Windows idle waits use a high-resolution waitable timer, the process opts out of power throttling, game threads are MMCSS "Games". The installer builds unchecked unless `-Checked`.

The run report's "audio frames (N mixed by the DSP)" must match.
